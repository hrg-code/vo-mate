# AI 自媒体工作台 UI/UX 设计标准

版本：v0.1  
日期：2026-05-09  
适用范围：React Web 工作台、Electron 采集端、浏览器插件侧边栏。

## 1. 设计目标

AI 自媒体工作台不是营销官网，也不是单纯聊天机器人。它是一个给创作者长期使用的生产型工具，第一屏必须能直接进入工作状态。

设计目标：

- 让用户快速理解账号表现、内容机会和下一步动作。
- 让 AI 建议有依据、有置信度、可追溯、可修改。
- 让数据分析、选题、脚本、SEO、发布、复盘形成连续工作流。
- 让复杂数据在高密度界面中保持清晰、安静、可扫描。
- 让系统越用越懂用户，但不制造不可控的黑箱感。

## 2. 产品气质

关键词：

- 专业
- 冷静
- 高效
- 可信
- 数据驱动
- 创作友好
- 可解释

避免：

- 营销页式大 hero。
- 过度装饰。
- 大面积渐变背景。
- 一屏只有口号没有操作。
- 把 AI 包装成神秘魔法。
- 用卡片堆叠卡片导致界面臃肿。

## 3. 用户心智模型

用户进入系统时，通常带着四类问题：

| 问题 | UI 应回答 |
| --- | --- |
| 我现在表现怎么样 | 首页指标、异常提醒、趋势图 |
| 我接下来拍什么 | 选题雷达、机会分数、历史依据 |
| 这条内容怎么写 | 脚本工作台、标题、简介、标签、SEO |
| 发完以后学到了什么 | 复盘中心、成功/失败模式、记忆沉淀 |

因此页面组织应围绕“看数据 -> 找机会 -> 生成内容 -> 发布计划 -> 复盘学习”展开。

## 4. 体验原则

### 4.1 工作台优先

首页不是欢迎页，而是任务驾驶舱。用户打开后应立即看到：

- 今日建议。
- 核心指标。
- 待处理任务。
- 推荐选题。
- 最近异常内容。

### 4.2 数据先于生成

AI 生成前必须先展示或说明依据：

- 参考的历史视频。
- 使用的关键词。
- 目标平台。
- 目标人群。
- 置信度。
- 风险点。

### 4.3 AI 可控

所有 AI 输出都应允许用户：

- 重生成。
- 局部改写。
- 调整语气。
- 切换平台。
- 查看依据。
- 保存版本。
- 标记好/差。

### 4.4 高密度但不压迫

这是运营工具，不是内容展示网站。页面要支持大量信息扫描，但需要明确层级：

- 左侧导航稳定。
- 顶部保留上下文和全局操作。
- 主区域以表格、图表、编辑器、任务流为主。
- 右侧用于 AI 建议、依据、过滤器或详情。

### 4.5 默认给下一步

每个关键页面都应有一个“下一步动作”：

- 视频详情：生成复盘。
- 复盘报告：生成承接选题。
- 选题详情：生成脚本。
- 脚本草稿：生成标题/SEO。
- SEO 完成：加入发布计划。
- 发布后：等待采集并复盘。

## 5. 信息层级

### 5.1 页面层级

| 层级 | 用途 | 示例 |
| --- | --- | --- |
| L1 全局导航 | 模块切换 | 首页、视频库、选题雷达、脚本工作台 |
| L2 页面标题区 | 当前上下文 | 账号、平台、时间范围、主要动作 |
| L3 工作区 | 核心任务 | 表格、图表、编辑器、日历 |
| L4 辅助区 | AI 建议、过滤器、依据 | 右侧抽屉、侧栏 |
| L5 临时层 | 确认、编辑、查看详情 | Modal、Drawer、Popover |

### 5.2 内容优先级

优先展示：

- 结果。
- 趋势。
- 异常。
- 建议动作。
- 依据。

延后展示：

- 完整原始 JSON。
- 底层采集日志。
- 长 prompt。
- 低频设置。

## 6. 布局标准

### 6.1 App Shell

标准桌面布局：

```text
┌────────────────────────────────────────────────────────────┐
│ Top Bar: workspace / account / search / tasks / user       │
├──────────────┬─────────────────────────────────────────────┤
│ Side Nav     │ Page Header                                 │
│              ├─────────────────────────────────────────────┤
│              │ Main Work Area                              │
│              │                                             │
│              │ Optional Right Panel / Drawer               │
└──────────────┴─────────────────────────────────────────────┘
```

尺寸建议：

- 左侧导航宽度：`240px`，收起后 `64px`。
- 顶栏高度：`56px`。
- 页面标题区：`64-96px`。
- 主内容最大宽度：数据页不限制；编辑页建议 `1440px` 内约束。
- 右侧面板宽度：`360-480px`。

### 6.2 页面网格

- 基础间距：`4px`。
- 常用间距：`8px`、`12px`、`16px`、`24px`、`32px`。
- 页面外边距：桌面 `24px`，小屏 `16px`。
- 卡片内边距：紧凑 `12px`，标准 `16px`，复杂内容 `20px`。
- 表格行高：紧凑 `40px`，标准 `48px`。

### 6.3 容器形态

允许使用卡片：

- 指标卡。
- 视频列表项。
- 推荐选题。
- AI 生成结果。
- Modal 内容。
- 独立工具面板。

避免：

- 页面大区域都包成悬浮卡片。
- 卡片内再嵌套卡片。
- 纯装饰性卡片。

### 6.4 圆角

- 默认圆角：`8px`。
- 小控件圆角：`6px`。
- 表格、输入框、按钮：`6-8px`。
- 不使用过度圆润的胶囊形控件，除非是标签或状态徽章。

## 7. 视觉系统

## 7.1 色彩

设计方向：浅色、安静、专业，保留清晰的状态色和平台色，不做单一色系页面。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `bg.canvas` | `#F7F8FA` | 页面背景 |
| `bg.surface` | `#FFFFFF` | 面板、卡片 |
| `bg.subtle` | `#F1F3F5` | 次级区域 |
| `text.primary` | `#1F2328` | 主文字 |
| `text.secondary` | `#5B6472` | 次级文字 |
| `text.muted` | `#8A94A3` | 辅助文字 |
| `border.default` | `#DDE2E8` | 默认边框 |
| `brand.primary` | `#2563EB` | 主按钮、关键操作 |
| `brand.teal` | `#0F9F8F` | 正向洞察、增长 |
| `brand.amber` | `#B7791F` | 机会、提醒 |
| `brand.red` | `#D64545` | 风险、错误 |
| `brand.violet` | `#7C3AED` | AI 标识、小面积强调 |

使用规则：

- 主界面不以紫色或蓝紫渐变作为大面积背景。
- 数据可视化至少包含 4 组可区分颜色。
- 平台色只作为标识，不主导页面。
- 红色仅用于风险、失败、删除和负向指标。

### 平台色

| 平台 | 色彩建议 | 用途 |
| --- | --- | --- |
| 抖音 | `#111111` + `#00F2EA` + `#FF0050` | 平台徽标、小标签 |
| 快手 | `#FF6600` | 平台徽标、小标签 |
| 小红书 | `#FF2442` | 平台徽标、小标签 |
| YouTube | `#FF0000` | 平台徽标、小标签 |
| 视频号 | `#07C160` | 平台徽标、小标签 |

## 7.2 字体

字体栈：

```css
font-family: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

字号：

| Token | 大小 | 用途 |
| --- | --- | --- |
| `text-xs` | `12px` | 标签、辅助信息 |
| `text-sm` | `14px` | 表格、表单、正文 |
| `text-md` | `16px` | 重点正文、输入 |
| `text-lg` | `18px` | 区块标题 |
| `text-xl` | `20px` | 页面小标题 |
| `text-2xl` | `24px` | 页面标题 |
| `text-3xl` | `30px` | 首页关键数字 |

规则：

- 不使用视口宽度动态缩放字体。
- 字间距保持 `0`。
- 数据页面避免超大标题。
- 表格和编辑器优先保证可读密度。

## 7.3 图标

- React Web 优先使用 `lucide-react`。
- 工具按钮使用图标优先，例如搜索、筛选、刷新、下载、保存、复制。
- 不熟悉的图标必须有 tooltip。
- 关键破坏性操作不可只用图标，需加文字或确认。

## 7.4 图表

图表目标是辅助判断，不做装饰。

推荐图表：

- 趋势：折线图。
- 构成：水平条形图、堆叠条形图。
- 对比：柱状图。
- 分布：条形图、热力图。
- 多指标表现：雷达图谨慎使用，只用于概览。
- ASR 时间轴：分段条 + 文本列表。

图表规则：

- 必须展示单位。
- 必须有空状态。
- 指标异常需要标注。
- 支持 hover tooltip。
- 支持时间范围切换。
- 不使用 3D 图表。

## 8. 状态设计

### 8.1 Loading

| 场景 | 设计 |
| --- | --- |
| 首屏数据 | 骨架屏 |
| 图表 | 图表区域 skeleton |
| 表格 | 保留表头，行 skeleton |
| AI 生成 | 进度状态 + 当前步骤 |
| 长任务 | 任务状态条 + 可后台运行 |

### 8.2 Empty

空状态需要给下一步：

- 没有视频：引导导入历史数据。
- 没有选题：引导输入方向或从历史数据生成。
- 没有脚本：引导从选题生成。
- 没有记忆：引导先做一次复盘。

### 8.3 Error

错误信息必须包含：

- 发生了什么。
- 是否可重试。
- 下一步怎么做。
- 技术详情折叠展示。

### 8.4 AI 任务状态

| 状态 | UI |
| --- | --- |
| `queued` | 等待中 |
| `retrieving` | 正在查找历史依据 |
| `reasoning` | 正在分析 |
| `generating` | 正在生成 |
| `reviewing` | 正在检查 |
| `completed` | 完成 |
| `failed` | 失败，可重试 |

## 9. AI 可信体验标准

每个 AI 结果必须包含：

- 结论。
- 依据。
- 置信度。
- 可操作建议。
- 风险提示。

AI 建议展示结构：

```text
结论
为什么这样建议
参考了哪些历史内容
建议怎么做
风险或不确定性
```

禁止：

- 只给最终答案不解释。
- 伪造数据。
- 把推测说成事实。
- 隐藏低置信度。

## 10. 响应式标准

### 桌面端

- 完整侧边导航。
- 支持三栏：导航 + 主工作区 + 右侧 AI 面板。
- 表格和编辑器为主。

### 平板

- 侧边导航可收起。
- 右侧 AI 面板变为 Drawer。
- 表格支持横向滚动。

### 手机

- 仅支持轻量查看和审批。
- 底部导航。
- AI 结果、复盘报告、选题卡片优先。
- 大型编辑器和复杂图表可提示“桌面端体验更完整”。

## 11. 可访问性

- 所有交互元素可键盘访问。
- 所有图标按钮有 `aria-label`。
- 颜色对比度至少满足 WCAG AA。
- 错误提示不只依赖颜色。
- 表格支持排序状态读出。
- Modal 和 Drawer 打开时焦点锁定。
- Toast 不作为唯一反馈，关键结果需要页面内保留。

## 12. 文案标准

### 语气

- 清楚。
- 直接。
- 专业。
- 不夸张。
- 不制造焦虑。

### 推荐表达

- “基于过去 30 条同类内容，推荐继续做这个方向。”
- “这个选题搜索潜力高，但历史完播率偏低。”
- “建议先生成 60 秒口播，再改写成小红书版本。”

### 避免表达

- “必爆。”
- “全网最强。”
- “系统认为你必须这样做。”
- “AI 已经完全理解你的账号。”

## 13. 设计质量检查清单

每个页面交付前检查：

- 第一屏是否有明确操作。
- 主任务是否在 3 次点击内可完成。
- AI 输出是否有依据和置信度。
- 表格、图表、编辑器是否有空状态。
- 移动端是否没有明显内容重叠。
- 长文本是否不会撑破容器。
- 主要按钮是否唯一且清晰。
- 危险操作是否有确认。
- 页面是否没有大面积无意义装饰。
- 是否符合工作台而非营销页的气质。
